# 원격 갤러리·애니메이션·알림 정책

## 원격 목록

GalleryCatalogStore는 Application Support/Gallery/catalog-v1.json에 마지막 정상 목록을
보관하고 초기 화면에 먼저 표시한다. 정상 캐시가 없을 때만 번들 11개를 사용한다.
GET /v1/gallery: schemaVersion=1, revision=정규화된 팩 이름을 줄바꿈으로 연결한 SHA256,
packs=[{name,link}]. 목록은 최대 200개, KV 원문 64KiB. 중복 제거 후 최초 순서를 유지한다.
빈 값은 유효한 빈 목록이며 조회 실패/유효성 오류와 구분한다.
갤러리 진입/활성 복귀 시 60초 throttle, 당겨서 새로고침은 앱 throttle을 우회한다.
KV 자체의 eventual consistency 지연은 우회하지 못한다.
제거된 추천은 선택 상태에서만 제거하며 설치 팩이나 시작한 다운로드는 건드리지 않는다.
관리 방법은 backend/worker/README.md에 설명했다.

## 미리보기

보이는 카드의 앞 3개 항목만 처리한다. 설치 팩의 thumbnail/playback GIF를 먼저 재사용하며,
미설치 항목은 썸네일 먼저 표시 후 원본 TGS/WebM을 96px/15fps GIF로 변환한다.
GalleryPreviewStore는 네트워크 2개, 변환 1개, 디스크 LRU 100MiB이며 보이는 파일과
처리 중 파일을 제거하지 않는다. 캐시 키는 팩/항목 ID/형식/선언 크기/해상도/캐시 버전으로 만든다.
캐시 경로는 Library/Caches/GalleryPreviews/v1이며 기존 캐시 용량 집계에 포함된다.
동작 줄이기에서는 원본 애니메이션을 다운로드/변환하지 않고 포스터만 표시한다.
화면 밖/탭 이탈/백그라운드/진행 작업 중에는 해당 미리보기 작업을 취소하고 재생을 멈춘다.
스크롤 자체로는 보이는 GIF 재생을 중단하지 않는다.
캐시 삭제/초기화/최적화 후 정리는 beginMaintenance → 작업 취소 및 종료 대기 → 삭제 →
endMaintenance 순서다. 진행 작업을 시작할 때도 미리보기를 먼저 취소하고 종료를 기다린다.
설치 데이터는 미리보기 캐시와 별개이며 갤러리 미리보기로 설치 상태가 바뀌지 않는다.

## 알림

BackgroundWork.Kind에서 다운로드/업데이트/원본 복원/최적화 준비/최적화 적용을 명시한다.
시스템 알림 발송은 BackgroundWork.end에만 모으고 한 작업 ID는 제거 후 재발송하지 않는다.
성공/일부 실패/실패는 최종 결과 1회, 취소는 0회다. 캐시/팩/전체 스티커 삭제와 미리보기는
알림을 발송하지 않으며 알림 권한도 요청하지 않는다. 앱 내부 최적화 유도 팝업은 유지한다.

## 확인 범위

Worker TypeScript 타입 검사와 앱 빌드, 배포 후 실제 초기 목록 응답 확인.
자동 테스트는 사용자 지시대로 실행하지 않았다. GIF 재생/스크롤/캐시 삭제 동시 동작,
목록 편집 반영/오프라인/빈 목록, 시스템 알림 횟수의 실제 UI 동작은 미검증이다.
