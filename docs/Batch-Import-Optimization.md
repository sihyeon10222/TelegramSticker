# 여러 팩 설치와 선택 최적화

## 동작

- Telegram 링크 추가 화면에서 `링크 추가 (+)`로 입력칸을 늘리고 `입력한 팩 모두 설치`를 선택한다.
- 팩은 순차 처리한다. 잘못된 링크·없는 팩은 원인을 표시하고 다음 팩을 계속한다. 중복 링크·설치 완료한 팩은 건너뛰고, 부분 설치 팩은 실패 항목을 재시도한다.
- 일괄 작업 링크 목록은 앱 전용 저장소에 원자적으로 보관한다. 시스템 종료 후 다시 열면 목록을 복원한다. 접근키·Bot 토큰은 이 파일에 기록하지 않는다.
- 파일 다운로드 세 개를 병행하고, CPU·메모리 사용이 큰 변환은 공통 gate에서 하나씩 처리한다. 다운로드와 변환이 겹쳐 진행되며 외부 서버의 속도를 보장하지 않는다.

## 선택·비교·적용

- 홈 `편집`에서 여러 팩을 선택한 뒤 `업데이트` 또는 `최적화`를 실행한다. 업데이트는 Telegram 팩에만 제공한다.
- 팩 상세의 `선택`에서 스티커를 복수 선택하거나, 큰 미리보기의 `최적화`에서 하나만 선택한다.
- 설정의 `스티커 용량 최적화`는 전체 설치 팩을 대상으로 같은 비교 화면을 연다.
- 기본 `화질 우선`: 최대 384px / GIF 최대 24fps. `용량 우선`: 최대 256px / GIF 최대 15fps.
- 최대 크기는 상한이다. 작은 이미지나 프레임 수를 늘리지 않는다. 실제로 작아진 파일만 사용한다. 투명 PNG·GIF, 재생 길이·루프를 보존하며, 손실 없는 최적화라는 뜻은 아니다.
- `비교 버전 만들기`는 별도 임시 라이브러리에서 변환한다. 설치된 인덱스·파일·클립보드는 변경하지 않는다.
- 원본과 최적화 버전을 같은 크기로 나란히 표시하고, 두 이미지를 함께 확대할 수 있다. 항목별 PNG+GIF 용량 및 전체 선택 팩의 저장 용량·예상 절약량을 표시한다. 전체 예상량에는 썸네일·키보드 재생 파일·manifest도 포함한다.
- `비교한 최적화 버전 적용`을 누르면 비교에 사용한 후보 파일을 사용한다. 팩별 이전 revision을 다시 확인하고 원자적으로 게시한다. 비교 중 업데이트·삭제된 팩은 덮어쓰거나 되살리지 않는다.
- 적용 실패는 기존 팩을 유지한다. 전체 작업의 팩 단위 원자성이므로 이미 완료된 다른 팩까지 롤백하지 않는다.
- 게시 후 교체된 revision만 삭제하여 실제 공간을 확보한다. 정리 실패는 별도 안내하며 캐시 삭제로 재시도한다.
- 적용한 뒤 원본을 복구하려면 삭제 후 재설치가 필요하다. 비교 화면에서 먼저 확인한다. 후보 생성에는 추가 임시 저장 공간이 필요하다.

## 백그라운드

- 메인 앱에 `BGContinuedProcessingTask`의 CPU/network 기본 자원을 사용한다. GPU entitlement, 별도 Widget 타깃, 확장 네트워크 요청은 추가하지 않는다.
- 생성·적용·단일 설치·일괄 설치/업데이트를 foreground에서 시작해 시스템에 continued-processing 실행을 요청한다.
- 실제 완료한 항목 수를 Progress에 보고한다. 시스템이 Live Activity 및 진행 표시를 관리한다. Dynamic Island의 상세 표현은 iOS가 결정한다.
- 사용자 취소·만료 시 Swift Task를 취소하고 작업을 종료한다. 홈으로 이동하는 동작과 앱을 강제 종료하는 동작은 다르며, 강제 종료 후 무제한 실행을 보장하지 않는다.
- 요청이 거절되면 앱 내에 사유 코드를 포함한 안내를 표시하고 foreground에서 진행한다. Simulator는 백그라운드 지원 검증 대상에서 제외한다.
- 가져오기 화면을 닫아도 이미 시작한 설치는 취소하지 않는다. 시스템 Live Activity와 앱 하단 진행 표시에서 중단할 수 있다.

공식 근거: [Apple BGContinuedProcessingTask](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtask), [장시간 작업](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados).

## 검사

- 원본과 임시 비교의 분리, 선택 범위, 예상/실제 절약량, 알파, GIF 시간·루프, 재최적화 방지, 게시 실패 시 인덱스 보존, 삭제된 팩 복구 방지 단위 검사.
- 링크 입력칸 추가 → 일괄 설치 → 홈 선택 → 최적화 비교 UI 검사.
- 실기기 백그라운드 검사는 `STICKERBRIDGE_BACKGROUND_VALIDATION=1`을 설정해 `PhysicalBackgroundWorkTests/testComparisonContinuesAfterLeavingApp` 실행. 기존 두 Telegram 팩 중 하나의 임시 비교만 만들고 실제 최적화는 적용하지 않는다.
- 기기에서 확인하지 않은 Live Activity/Dynamic Island 동작과 실제 서버 속도 향상 수치는 검증 완료로 취급하지 않는다.
