# 권한 안내·초기화·백그라운드 처리 (2026-10-15)

- 첫 실행/설정에 전체 접근 안내와 공식 openSettingsURLString 버튼을 제공한다. 앱 설정 화면까지 이동하며 하위 키보드 스위치를 자동 변경하지 않는다.
- 키보드가 hasFullAccess=true를 확인하면 App Group에 관찰 시각만 기록한다. 채팅/클립보드는 읽지 않는다. 메인 앱에서 현재 권한을 직접 조회하는 API는 없으므로 이 기록은 현재 권한 보장이 아니다. 허용 관찰 기록이 없으면 다운로드/최적화 시작과 앱 복사 시 설정 안내를 표시하지만 해당 작업을 차단하지 않는다.
- 초기화는 두 차례 확인 후 빈 인덱스를 원자 게시하고 팩·staging·앱 캐시·임시 파일·Documents·Application Support·앱 preferences·기존 수동 연결 Keychain 항목을 삭제한다. 실행 중인 가져오기/최적화가 있으면 금지한다. 키보드 프로세스의 개인 preferences는 메인 앱에서 접근할 수 없어 공유 reset epoch로 다음 키보드 진입 때 최근 사용/팩 순서/선택을 초기화한다. iOS가 관리하는 키보드 활성화/전체 접근/알림 권한은 초기화 대상이 아니다.
- continued processing 전략을 fail에서 queue로 변경했다. 작업 승인까지 UIApplication 실행 유예를 연결하고, 유예가 끝나고 백그라운드 승인이 없으면 네트워크/변환 체크포인트에서 기다린다. 시스템 expiration 또는 사용자의 취소는 정상적으로 취소한다.
- WebM의 synchronous 변환 및 TGS의 프레임별 45초 계산은 thread CPU time으로 처리하여 OS 스케줄링/앱 정지 시간을 변환 실패로 잘못 계산하지 않는다. 이미지 크기/프레임 수/손상 파일 검사와 취소 처리는 유지한다.
- URLSession 리소스 제한 시간은 600초로 늘렸다. 현재 세션은 OS 독립 background URLSession이 아니다. 시스템이 앱을 강제 종료하거나 실행 승인을 철회하면 연속 완료를 보장하지 않으며 기존 저장된 가져오기 초안/완료 파일로 재시도한다. 최적화 비교는 프로세스 종료 후 다시 준비해야 한다.

검증: Simulator 및 generic iOS (서명 비활성화) 빌드. 사용자 지시에 따라 테스트, 초기화 실행, 기기 설치 및 실제 백그라운드 동작 검증은 수행하지 않았다.


## 키보드 설정 경로 분리

사용자의 명시적 요청에 따라 ‘키보드 추가’는 `App-prefs:General&path=Keyboard/KEYBOARDS`
및 root 변형을 순서대로 시도한다. ‘전체 접근 허용’만 공식 openSettingsURLString을 사용한다.
추가 경로가 거절되면 앱 설정으로 잘못 대체하지 않고 수동 이동 안내를 표시한다.
App-prefs는 비공식 경로다. URL open 성공은 정확한 하위 화면 도착을 증명하지 않으며,
iOS 버전/앱 배포 조건에서 동작과 심사 적합성을 보장하지 않는다. 신규 개발에 적용할 공식 권장
방식이 아니라는 점에 주의한다. https://developer.apple.com/library/archive/qa/qa1924/_index.html
이 변경에서는 빌드만 수행하고 실제 기기에서 목적 화면 도착 여부는 검증하지 않았다.
