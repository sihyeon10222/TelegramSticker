# Milestone 5 — 후속 계획

작성 당시의 후속 계획입니다. 이후 사용자가 TGS/WebM을 우선 선택해 GIF 변환·저장·복사를 구현했습니다. 현재 범위와 남은 검증은 [애니메이션 검증 기록](AnimatedStickers-Validation.md)을 우선합니다. Messages 확장·iCloud·공개 출시는 계속 후속 범위입니다.

## 1. Messages 확장

기존 키보드가 가진 타 앱 붙여넣기 제약과 별도로 Apple 메시지용 스티커 사용 흐름을 제공합니다. 사용자가 선택하면 기존 프로젝트에 Messages 확장 타깃을 추가하고 App Group의 완료된 PNG와 manifest만 읽습니다. [MSSticker](https://developer.apple.com/documentation/messages/mssticker)를 생성해 메시지 전용 스티커 브라우저에 연결하는 기술 검증을 먼저 진행합니다.

- 선행 조건: 새 확장 Bundle ID·서명·App Group과 대상 OS에서의 공식 이미지 규격 확인.
- 작은 첫 구현: 자체 PNG 3개, 메시지 앱에서 삽입·사용자 전송·재진입 확인. 일반 키보드와 독립적으로 검증.
- 완료 기준: 실기기 메시지 작성창에서 선택한 스티커가 정상 표시되고 사용자 전송이 가능함.
- 위험/롤백: 메시지 전용 UI와 일반 키보드의 사용 방식이 달라짐. 새 확장 의존성·Embed 단계만 독립적으로 제거하고 기존 팩은 보존.

## 2. TGS/WebM 애니메이션

먼저 허가된 fixture로 디코더·프레임 렌더링·알파·출력 형식을 조사합니다. 앱 변환과 서버 변환의 CPU·메모리·전송량·Worker 실행 한도·라이브러리 라이선스를 비교한 뒤 한 포맷만 선택해 검증합니다. 현재 Worker에 고비용 변환을 바로 넣지 않습니다.

- 선행 조건: 목표 수신 앱과 전달 형식, 프레임·길이·출력 크기 상한, 필요한 외부 의존성의 유지보수·라이선스 확인.
- 작은 첫 구현: TGS 또는 WebM 한 종류의 미리보기만 구현. 키보드에서 변환하거나 자동 재생하지 않음.
- 완료 기준: 렌더링 결과의 투명도·프레임·메모리를 실측하고, 선택한 수신 앱에서 붙여넣기·전송 결과를 별도 확인.
- 위험/롤백: 애니메이션을 복사해도 앱이 정지 이미지로 취급할 수 있음. 새 포맷 경로를 끄고 정적 PNG 경로 유지.

## 3. 선택적 iCloud 동기화

공유 저장소를 직접 여러 기기의 동기화 디렉터리로 바꾸지 않고, 동기화 계층이 받은 파일을 기존 writer가 검증·게시하도록 설계합니다. [CloudKit](https://developer.apple.com/documentation/cloudkit) private database와 파일 동기화 방식을 비교합니다.

- 선행 조건: iCloud capability, 사용자 opt-in·로그아웃 정책, 저장량·비용과 데이터 삭제 정책.
- 작은 첫 구현: 팩 메타데이터 동기화, 그다음 자체 샘플 파일. 대용량 스티커는 후속.
- 완료 기준: 두 기기의 오프라인 수정·중복·삭제·순서 충돌과 계정 변경 시 복구 확인.
- 위험/롤백: 삭제 tombstone·revision 충돌 및 quota. 동기화만 중단해도 현재 기기의 로컬 팩을 계속 사용하도록 유지.

## 4. 공개 백엔드와 App Store 준비

현재 ACCESS_KEY는 개인 테스트용입니다. 공개 앱에 고정 접근키를 내장하지 않습니다. [App Attest](https://developer.apple.com/documentation/devicecheck/establishing-your-app-s-integrity)의 서버 검증, 재전송 방지, 세션 발급·회수와 사용량 상한을 작은 별도 검증으로 설계합니다. IP rate-limit은 정확한 전역 과금 상한이 아니므로 모니터링·차단 절차를 함께 마련합니다.

출시 전에는 다음을 별도 완료해야 합니다.

1. Keyboard Guideline 4.4.1의 문자 입력·Full Access 미허용 기본 기능 대응 결정. 현재 문자 버튼은 구현하지 않았으며, 소수 버튼으로 심사 통과를 보장하지 않음.
2. 제공 팩·미리보기·캐시의 이용 권한과 Telegram 약관 검토. 공개 링크를 재배포 허가로 간주하지 않음.
3. 개인정보 처리방침·지원 URL·수집 항목·서버 로그 보존과 App Privacy 응답의 실제 운영 일치.
4. iPad 실기기, VoiceOver, 장시간 확장 메모리와 앱별 붙여넣기·투명도 결과 보완.
5. 배포 서명·App Store Connect 정보·심사용 데모/서버 접근·스크린샷 준비.

문제가 발생하면 공개 가져오기를 중단해도 기존 다운로드 팩은 유지합니다. App Store 제출·최소 문자 입력 기능·새 확장은 사용자가 해당 실행을 선택한 뒤 진행합니다.

## 권장 후속 순서

개인 사용을 계속한다면 실제 사용 중 발견한 오류를 우선 수정합니다. 제품 확장이 목적이면 Messages 확장 검증을 먼저, 애니메이션·iCloud는 그다음 선택합니다. 공개 출시는 인증·권리·심사·실기기 검증을 별도 작업으로 묶어 진행합니다. 현재 M4에서 남긴 미검증 사항은 [검증 기록](Milestone4-Validation.md)을 기준으로 유지합니다.
